## 1. 上下文

CodeFree 会话的 state JSON 只包含 session 级 `startTime` 和 `modifiedTime`，没有 per-turn 或 per-message 时间戳。这导致 UI 中所有消息显示同一个时间，无法区分消息先后顺序。

CodeFree IDE 在运行时会产生日志文件 `agenthost.log`，位于 `agentSessionData` 目录的兄弟目录 `logs/` 下。日志中包含 "Turn started" 行，格式为 `YYYY-MM-DD HH:MM:SS.mmm [info] [CodeFree] Turn started session=会话ID turn=轮次ID ...`，提供了 per-turn 的真实时间戳。state JSON 中的 `history.turnId` 字段与日志中的 `turn=` 值对应。

然而日志文件可能部分缺失（某些 turn 的日志行丢失）或全部缺失（日志被清理或新安装无日志），需要一种策略在所有场景下都能提供合理的时间戳。

## 2. 决策驱动因素

- 时间戳精度越高越好：真实日志时间戳优于估算值
- 必须覆盖所有场景：日志全部可用、部分可用、全部缺失
- 部分缺失时不应将所有缺失 turn 挤在同一时间点，需要保持时间顺序
- 实现复杂度可控：策略逻辑清晰，可单元测试覆盖各场景
- 不影响现有功能：日志扫描失败不阻止会话解析

## 3. 备选方案

### 3.1 方案A：三级兜底策略（日志真实值 → 相邻线性插值 → session 级均匀插值）

- 方案说明：
  - Pass 1：从 `codefreeLogTimestampMap` 中按 `sessionID/turnId` 查找日志真实时间戳，填充到对应 turn
  - Pass 2：对未命中的 turn，在相邻已知 turn 之间线性插值。前导缺失用第一个已知 turn 的时间戳；尾部缺失用最后一个已知 turn 的时间戳；中间缺失在前后已知 turn 之间均匀分配
  - Pass 3：若全部 turn 均无日志时间戳，用 session `startTime` 和 `modifiedTime` 在所有 turn 之间均匀插值
- 优点：覆盖所有场景；时间戳精度从高到低优雅降级；部分缺失时保持时间顺序
- 缺点：实现逻辑较复杂，需要三次遍历
- 风险：插值时间戳是估算值，与真实时间可能有偏差（可接受，优于无时间戳或统一时间戳）

### 3.2 方案B：仅用日志值，缺失时用 session startTime

- 方案说明：从日志映射中查找时间戳，未命中的 turn 统一使用 session `startTime`
- 优点：实现简单
- 缺点：部分缺失场景下大量 turn 挤在同一个时间点（session startTime），无法区分先后顺序；与已有 turn 的时间戳可能产生时间倒流
- 风险：UI 显示多个消息在同一时间，用户体验差

### 3.3 方案C：仅用 session 级均匀插值，不扫描日志

- 方案说明：不读取日志文件，直接用 session `startTime` 和 `modifiedTime` 在所有 turn 之间均匀插值
- 优点：实现最简单，不依赖日志文件
- 缺点：放弃真实时间戳精度，所有时间戳都是估算值；turn 间隔均匀分布与实际不符（实际 turn 间隔可能差异很大）
- 风险：时间戳精度低，无法反映真实的会话节奏

## 4. 决策

选择方案A：三级兜底策略（日志真实值 → 相邻线性插值 → session 级均匀插值）。

## 5. 决策理由

方案A 在所有场景下都能提供合理的时间戳，且精度从高到低优雅降级。方案B 在部分缺失场景下会产生大量相同时间戳，无法区分消息先后，与本次需求目标矛盾。方案C 放弃了可用的真实时间戳数据，精度最低。

方案A 的实现复杂度可控：`resolveTurnTimestamps` 函数通过三次遍历完成填充，每次遍历逻辑独立清晰，单元测试可分别覆盖全命中、部分命中、全缺失、前导缺失、尾部缺失、中间缺失、单 turn 等场景。插值偏差在可接受范围内，且优于无时间戳或统一时间戳的替代方案。

## 6. 后果

### 6.1 正面影响

- 所有场景下都有合理的时间戳，UI 可正确显示消息先后顺序
- 日志可用时提供真实时间戳，精度最高
- 部分缺失时通过插值保持时间顺序，用户体验良好
- 日志扫描是 best-effort，失败不影响会话解析

### 6.2 负面影响与代价

- 新增 `codefree_logs.go` 模块，增加代码维护量
- 日志扫描在会话加载时执行，增加少量 I/O 开销（典型场景下可忽略）
- 插值时间戳是估算值，与真实时间可能有偏差

## 7. 实施与验证

- 实施要求：新增 `internal/parser/codefree_logs.go`，实现 `loadCodeFreeLogTimestamps` 和 `resolveTurnTimestamps`；在 `codefree.go` 中集成日志扫描和三级填充；在 `codefree_provider.go` 中传递 `root` 参数
- 验证方式：
  - `TestResolveTurnTimestamps_AllFromLog`：全部 turn 有日志时间戳
  - `TestResolveTurnTimestamps_PartialFromLog`：部分 turn 有日志时间戳
  - `TestResolveTurnTimestamps_InteriorGap`：中间缺失插值
  - `TestResolveTurnTimestamps_LeadingGap`：前导缺失用首个已知值
  - `TestResolveTurnTimestamps_TrailingGap`：尾部缺失用末尾已知值
  - `TestResolveTurnTimestamps_NoLogEvenDistribution`：无日志时均匀插值
  - `TestResolveTurnTimestamps_NoLogSingleTurn`：无日志单 turn 用 session startTime
- 回滚条件：变更后消息时间戳显示异常或日志扫描导致解析性能显著退化
